# Internationalisation (i18n)

## Fonctionnement
- **Catalogues** : `app/translations/<locale>.php`, tableaux plats `clé => texte`. `fr` est la source ;
  `en`, `nl`, `de` fournis.
- **Traduction** : `App\I18n\Translator` (params `{name}`, repli sur la locale par défaut puis sur la clé).
- **Résolution de locale** : `App\I18n\Locale::resolve($config, $profileLocale)` — ordre : `?lang` explicite >
  profil utilisateur > cookie `lang` > `Accept-Language` > défaut. Un `?lang` valide est mémorisé en cookie (1 an) ;
  pour un utilisateur connecté, la page compte le persiste aussi dans son profil.
- **Formatage** : `App\I18n\Formatter` (dates, nombres, devises) via **ext-intl** si présent, sinon repli neutre.
- **Rendu** : `App\View\ViewFactory::create($templateDir, $locale, $default)` construit une `View` exposant aux
  templates : `t()` / `te()` (traduit [+ échappe]), `money()`, `num()`, `dt()`, `locale()`.

## Ajouter une langue
1. Copier `app/translations/fr.php` en `app/translations/<xx>.php` et traduire les valeurs.
2. Ajouter `<xx>` à `i18n.available` dans `app/config/config.php` (voir `config.example.php`).
3. C'est tout : le sélecteur de langue et la résolution la prennent en compte automatiquement.

## Couverture
- **Localisées** : page de connexion (Basic Auth), pages légales (CGU / confidentialité), page « Mon compte »
  (profil, jetons, EnergyID, RGPD), messages d'erreur associés — avec sélecteur de langue.
- **Restant (mécanique, moteur prêt)** : `dashboard` (surtout des chaînes dans `assets/js/dashboard.js`) et
  `tariffs`. Conversion = remplacer les libellés par `$this->te('clé')` et ajouter les clés aux 4 catalogues.

## Note ext-intl
`ext-intl` est **suggéré** (pas requis) : sans lui, le formatage reste correct mais non localisé (séparateurs,
symboles). L'installer en production pour un rendu conforme à chaque pays.
